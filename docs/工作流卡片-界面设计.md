# 工作流卡片：界面设计与落地路线

> 这份文档记录两件事：**这一轮已经做进代码的东西**，和**还没做的东西落在哪**。
> 引擎侧的合同在 `dsh-flow/README.md`（`--events` 与步骤结果协议），工作流本身在
> `workflows/units-export/`。

---

## 0. 一句话现状

引擎现在用 `--events` 把每一步的**开始 / 结束 / 摘要 / 产物 / 结构化错误**逐行推给界面；
界面在左栏把它们按聊天式**一行一个动作**排出来（进入一步是一条带分割线的突出文字）。
**输入卡片（含 `secret: true`）已经能填、能跑、不会泄漏到命令行与日志**；密码在屏幕上默认是
`••••`，按住「显示」才看得到，能存进本机凭据库，并且卡片会写明这个值喂给哪几步。

工作流页现在是**左「运行对话」+ 右「静态源码板」**：左边逐条输出摘要/markdown/原始输出/产物/错误，
右边只回答“这一步做什么、代码长什么样”——点开卡片是清单片段与程序文件（高亮），不显示运行态、
也不与左栏联动。`stdout/stderr` 就是日志，独立的日志窗格已删除。每次运行结束写一份完整快照
（`data/workflows/<name>/runs/<runId>.json`）供复盘与排查。

还没做：独立画布地图、AI 工具流与思考的透传、人机接管（重试/跳过/确认）、工作流页的三档密度，
以及把运行对话接到真正的助手会话（§12 只到决定，代码还没写）。

## 2. 事件协议（唯一合同）

`dsh-flow run --events` 的 stdout 是 NDJSON：一行一个事件，**最后一行是普通汇总对象**。

```
{"type":"run/start","detail":"maers-units-export"}
{"type":"step/start","id":"paths","kind":"run"}
{"type":"step/end","id":"paths","kind":"run","status":"ok","durationMs":173,
 "command":"python steps/units.py paths --workspace .","summary":"workspace = …"}
{"type":"step/end","id":"login","kind":"use","status":"failed","durationMs":2748,
 "error":{"kind":"credential","message":"缺少 DeepSeek API Key…",
          "hint":"在界面「设置 → AI」里填写 Key…","where":"maers-login:read"}}
{"type":"run/end","status":"failed","durationMs":38275,"detail":"…"}
{"runId":"…","status":"failed","steps":{…},"vars":{…}}      ← 汇总，最后一行
```

- `step/start` 没有 `status`，界面按 `running` 处理；
- `run/end` 带 verdict，所以只读事件的消费者不必自己推断；
- 人读的进度仍然走 stderr（日志页签），结构化数据只走 stdout；
- 旧版引擎（没有 `--events`）仍然可用：解析器把非事件行攒起来当汇总。

### 步骤自己描述的字段（stdout JSON 的保留键）

```json
{
  "summary": "共 51 条（第 1–10 条）",
  "artifacts": [{"kind": "file", "name": "使用单位导出.xls", "path": "…"}],
  "error": {"kind": "regex-miss", "message": "分页条里没有「共 N 条记录」",
            "hint": "站点改版时正则要跟着改", "where": "maers_site.py:query",
            "expected": "共 51 条", "gotten": "每页：10…"}
}
```

- `artifacts`：最多 12 个；路径相对清单目录；**必须存在**；`.env` / 密钥类被拒；
- `error.kind` 只接受下面九种，其它一律归为 `engine`：

| kind | 什么时候 | 卡片会说什么 |
|---|---|---|
| `credential` | 缺账号/密码/API Key，或被拒 | 指出要填哪一张输入卡 |
| `config` | 路径、工作目录、缺依赖（xlrd） | 给出装什么、放哪里 |
| `selector-miss` | 元素不在页面 / 没渲染 / 菜单名变了 | 期望的选择器 vs 实际找到的 |
| `regex-miss` | 分页条等文本没匹配 | 期望的正则 vs 实际文本 |
| `image-unreadable` | 模型说验证码看不清 | 附上那张截图 |
| `assert` | 条数/表头/取值不符 | 期望 / 实际并排 |
| `timeout` | 等待文件、等待页面 | 等了多久、目录在哪 |
| `model` | 端点/模型/额度问题 | 指向「设置 → AI」 |
| `engine` | 兜底 | 原样显示消息 |

### 脱敏规则

`secret: true` 的输入值在**引擎侧**统一替换成 `***`，覆盖：日志行、trace 记录（`command` / `detail` /
`summary`）、步骤的 `stdout` / `stderr` / `text` / `json`、`vars`、汇总与 HTML 报告。界面不需要、也不应该
自己再遮一遍——它根本拿不到明文。长度 < 2 的值不参与替换（否则会把整段文本打成星号）。

## 3. 页面的信息层级

**2026-11-27 第二轮起**，工作流页是左右两栏（`src/app/flow.rs`）：

```
┌ 左：运行对话（聊天式，56%）───────────────┐ ┌ 右：静态源码板 ────────┐
│ ── 开始运行 · smoke-ui ────────────────     │ │ 输入 1/1        [运行] │
│ ── 1 greet · set · ok 1ms ─────────────     │ │ ┌ 1 greet  set ▸ ───┐ │
│ hello 界面                                  │ │ │ 生成一行问候       │ │
│ ── 2 report · run · ok 168ms ──────────     │ │ │ node steps/smoke.js│ │
│ 写好了 3 个产物 / stdout / 产物(3) / 🖼      │ │ │ who [界面]         │ │
│ ── 3 broken · run · failed 130ms ──────     │ │ └───────────────────┘ │
│ 错误类型 / 位置 / 期望·实际 / 建议           │ │ （点卡片＝这一段的   │
│ ── 运行结束 · 成功 · 302ms ────────────     │ │   清单＋程序源码）    │
└─────────────────────────────────────────────┘ └───────────────────────┘
```

- **左栏 = 运行对话**（`src/app/transcript.rs`）：只读、聊天式。两个标签「当前 / 历史」在标题区底部，
  样式与聊天页的「聊天 / 上下文」一致（24px 高、`text_xs`、灰色选中下划线、悬停变深）：
  「当前」是运行中或最新一次已结束的运行；「历史」列出这个工作流的所有运行（时间、状态、耗时、步数、
  run id），点一条进去看完整输出，左上「‹ 历史记录」返回列表。**在「历史」标签下右栏源码板整体隐藏**，
  左栏铺满整块下方区域，但内容列参考聊天页：最宽 900px，超出的宽度平均分到左右两边留白。
  历史记录本身是一张张卡片（圆角、边框、浅阴影、悬停变底色），点卡片进入该次运行。
  打开的历史记录和它的输出同样按这个 900px 阅读列居中排版。
- **当前标签没有运行可看时**（初始页面、或点过「新建运行」），左栏只显示一条居中提示：
  「请点击运行开始」——浅灰（`faint`）、`text_lg`、`Microsoft YaHei` 加粗，上下左右都居中。
- **进入一步是一条突出文字**（序号 / id / kind / 状态 / 耗时）——圆点 + 彩色文字，两侧没有分割线；
  这一步产生的内容整体缩进一级。摘要 / stdout / stderr / 错误 / 产物各是一行**带颜色的标签**：
  「结果」「输出」「错误输出」「错误」「产物」。超过一行（或 40 字）的内容先显示一行预览，
  点「▸ 展开」在缩进框里看全文（最高 320px，可滚轮滚动），「▾ 收起」收回。步骤之间只留很小的
  垂直空隙，上一步的结尾不会和下一步标题隔开一大片。
  结构化错误为空时整行不出现，不会留下「错误类型 ·」这种空壳。
- **产物按聊天界面的样子画，并且每个产物占一行、再缩进一级**：文件是扩展名徽标 + 名字 + 大小 +
  「所在文件夹」，点卡片用系统程序打开；图片直接显示缩略图（最高 480px）和文件名。
  运行开始/结束各一条同类文字。
- **右栏 = 静态源码板**（`src/app/flow_board.rs`）：每个步骤是一条**单线圆角的宽行**（1px 边框、
  无填充/阴影、铺满板宽），点开时边框变天蓝；**收起时只有标题、描述和该步必要的输入框**；
  展开后才显示计划说明、条件/保存/备注，以及该步的**清单片段**（带行号）与**程序文件 / 子流程清单**。
  代码块最高 420px，超过就纵向滚动（右侧有一条随滚动移动的细滚动条），文字**自动换行**、语法高亮、可复制；
  不显示状态/耗时/输出/错误，也不与左栏联动。
- **运行控制只有一个按钮**，按状态切换：初始/新建后是「运行」；运行中是「停止运行」；一次运行结束后
  是「新建运行」。点「新建运行」把刚才那次运行交给历史、清空左栏当前标签并恢复输入可编辑；
  在那之前，当前标签一直显示这次运行。运行中的停止、完成或失败都由同一个状态机切换按钮。
- **输入只有一个可编辑实例**：第一个读取它的步骤拥有输入框，其它步骤显示只读值；没人读的输入进顶部的
  「运行前」卡。原因见 §14.3。
- 顶部标题参照聊天页标题：`text_xl` 加粗、左侧对齐，状态 chip 紧随其后，描述一行；右侧只有一个
  24px 的「打开文件夹」图标按钮（悬停底色同聊天页图标按钮）。标题下面是一条 24px 高的标签带，
  再下面是 1 个设备像素的 `chrome` 细线；**不再显示清单路径**。
- **页面外壳**：标题区保持页面底色（与左栏同色）；标题以下的整块区域改用标题栏的 `chrome` 色，
  左上/右上圆角并裁剪内部内容；左栏单独铺 `canvas`（浅色下是白色）、右上圆角，于是白栏像一张
  压在灰底上的卡片。最底部的状态条已删除，运行摘要只在左栏的运行结束行里。
- 原来的「264px 轨道 + 右侧检查器 + 底部日志 + 顶部最近运行 chips」已全部删除（历史进了左栏标签）。

## 4. 输入卡片

### 4.1 清单怎么写

```yaml
inputs:
  workspace:
    description: 浏览器会话与下载的落点
    default: .
  account:
    description: 站点账号
    secret: true          # 没有 default，也不允许有
  password:
    description: 站点密码
    secret: true
```

`secret: true` 的语义是三条：

1. **不能有 `default`** —— 引擎在 `loadWorkflow` 直接报错（"密码不进清单"）；
2. **不能走 `--input`** —— 传了就报错，并告诉你三条可用路径；
3. **只有三个来源**：界面的输入卡（随凭据一起走子进程 stdin）、`--secrets-stdin` 的 JSON、
   `DSH_SECRET_<NAME>` 环境变量。缺了会报 `credential`，并说明去哪填。输入卡的「保存到本机」
   （§4.2）只是卡片自己的记忆，对引擎来说仍然是同一个 stdin 来源。

### 4.2 输入卡现在能做什么

- **放在哪张卡**：输入长在它所属的步骤卡上——按清单的 `{{ inputs.x }}` 引用推断（第一个读取它的
  步骤），没人读的进顶部「运行前」卡；`use.inputs` 往子流程转发的输入（`account` / `password` /
  `vision_model`）会归到 `login` 卡。清单显式 `form:` 归属还没加（见 §14.5）。
- **掩码**：清单说 `secret: true` 的输入画成 `••••`（一个字符一个点）。方向键、`Ctrl+A`、
  删除、粘贴照常；光标按点在屏幕上的位置走，点一下就是点到的那一个字符。
- **按住显示**：卡片上的「按住显示」按下才露出明文，松开或把指针移出按钮立刻回到点。
  切换工作流、运行开始、输入框失去键盘时也会自动收起。
- **保存到本机**：写进 Windows 凭据管理器，键是
  `dsh-flow-ui/workflow:<清单名>:input:<输入名>`（名字里的 `:` / `/` 会折成 `_`）。
  下次打开同一张工作流，值自动填回，卡片亮「本机保存」徽标；改了内容徽标就消失，
  因为框里的值和库里已经不是同一个。
- **清除**：删掉本机记录并把输入框清空。只删库、不清框，会让下一次运行继续用刚被删掉的值。
- **这个值喂给哪几步**：卡片第二行「用于 N 步 · paths, login」，来自清单里的
  `{{ inputs.x }}`、`{{ inputs['x'] }}`，也包含 `use.inputs` 往子流程的转发。
  一次都没被引用的 secret 会直接写「清单里没有步骤读它」。
- **运行前校验**：必填为空时卡片实时标红；点「运行」会列出缺哪些输入并直接返回，
  **不启动子进程**。默认值、类型、路径这些仍由引擎判定。
- 清单仍不允许给 secret 写 `default`（引擎加载时会拒）；界面也不给 secret 预填 `default`，
  占位符不再说「default」。

### 4.3 还没做

| 待做 | 为什么现在没做 | 大致做法 |
|---|---|---|
| 独立的「校验」按钮 | 现在只有必填/空值这一条格式检查，且与「运行」绑在一起 | 先定义格式规则（路径存在、字符集、长度），再做一个绝不提交运行的检查动作 |
| 路径类输入接「选择文件夹」 | 选择器已经有了（附件、数据页），输入卡还没接 | 复用同一个 picker，结果写回 `InputField`；secret 不接选择器 |
| 引用行点击跳转 | 卡片上的步骤名目前只是文字 | 与 §8 的选中联动：点名字 = 选中该步并滚到轨道上的位置 |

## 5. 错误卡

四个字段各司其职，界面按"结论 → 修法 → 定位 → 对比"排：

| 字段 | 界面位置 | 例子 |
|---|---|---|
| `kind` + `message` | 卡片状态与检查器第一行 | `regex-miss · 分页条里没有「共 N 条记录」` |
| `hint` | 检查器「建议」 | 站点改版时正则要跟着改；先人工看一眼 `.pagenav-div` 的文本 |
| `where` | 检查器「位置」 | `maers_site.py:query`、`maers-login:read` |
| `expected` / `gotten` | 检查器「期望 / 实际」 | `共 51 条` · `每页：10…` |

三个真实例子（都是这次跑出来的）：

- **缺 Key**：`credential` + `where=maers-login:read` + hint 指向「设置 → AI」；
- **验证码看不清**：`image-unreadable`，检查器的产物里就有那张截图，人一眼能判断是站点还是模型；
- **导出条数不符**：`assert`，期望 51 条 / 实际 0 条，`problems` 里逐条列出。

## 7. AI 环节

**现状**：工作流里的 `ai` 步骤是**一次性问答**（`AiSpec` 只有 prompt/system/schema/images），

所以今天卡片能说"模型这一步失败是因为没填 Key"，但看不到模型的思考与工具调用。

**待做**（这件事要引擎与界面一起动）：

1. `AiSpec.tools: true` + 白名单（`browser` / `read` / `http`）——和聊天里的工具循环同一套实现
   （`agent.ts` + `tools.ts`），只是把"允许用什么"写死在清单里；
2. `run --events` 增加三种事件：`ai/delta`（过程文本）、`ai/reasoning`（思考）、`ai/tool`（工具行）；

4. 顺带把**发送给模型的图片**贴上（验证码那张），这是排查"模型读错了"的最短路径。

验收：一个带 `tools: true` 的 `ai` 步骤，运行中能在卡片里看到工具行在滚，结束后能展开看每一行。

## 8. 画布地图（明确的"只读"，不是主界面）

为什么不做主界面：清单是线性 DSL，节点间的"连线"只有执行顺序（恒定）与数据依赖（`save:` 与
`{{ steps.x… }}` 能推出来）。手工拖拽连线没有自由度，只有维护成本；而 12 步 × 每步的输入/结果/错误
在小节点里放不下。

所以画布只做**第三视图**：

- 自动布局（输入 → 步骤 → 交付），只画**数据依赖**，执行顺序用序号 + 一条淡色主轴；
- 节点 = 轨道里的紧凑卡，点上 → 轨道滚动定位 + 选中；
- `use` 子流程节点可展开，`map` 显示 `×N`；
- **不提供编辑**（可视化编程是另一个产品，需要反向生成清单与冲突合并）；
- 唯一的自动弹出场景：**失败**时切到地图，把失败节点与上下游高亮。

落点：新增 `src/app/flow_map.rs`，复用 `Pane.rows`；依赖边从 `manifest.rs` 解析出的 `save`/模板引用推导。

## 9. 人机接管（决策通道）

现在引擎只会"跑"：卡住了就失败，重试用尽就整条失败。要支持卡片上的**重试 / 跳过 / 确认**，
需要一条反向通道——协议照抄 `dsh-flow ai` 的 `interactive` 审批（同一条 stdin、同一个解析器）：

```json
{"type":"decision","step":"export","action":"retry"}     // 或 skip / allow / abort
```

- 引擎在需要人决定时打一条 `human/request` 事件（带 `step`、`reason`、可选 `options`），然后阻塞读 stdin；
- 界面在卡片上画动作按钮（与聊天里的审批卡同一套样式，`src/app/chat_actions/approval.rs`）；
- 超时/取消/窗口关闭一律按 `abort`，不会静默放行。

典型场景：`approve`（导出前确认筛选条数）、`pause`（验证码重试用尽转人工输入）、
失败后的 `retry`（只重跑这一步，不重跑整条流程）。

## 11. 已知限制（写在这里，免得踩第二次）

1. **`--events` 与 `--json` 互斥**：前者已经包含最后的汇总，两个一起给会报错。
2. **事件只覆盖顶层步骤与子流程边界**：`map` 里每一项的子步骤目前不发事件（等 §9 的通道一起做，
   否则事件 id 需要带下标）。
3. **`ai` 步骤仍然是一次问答**：没有 `delta`/`reasoning`，所以卡片上的"回答"是整段倒出来的。
4. **脱敏只认清单声明的 secret**：步骤自己从环境变量读到的密码，引擎不知道，遮不住——
   所以工作流的凭据要么走 `secret: true` 输入，要么步骤自己别打印。
5. **掩码只覆盖两类值**：清单声明的 `secret: true` 输入与接入点的 API Key；其余输入（路径、地区、
   导出名）照旧是明文——它们本来就该能一眼校对。secret 输入在「按住显示」期间也是明文，
   松开按钮、切换工作流、开始运行或输入框失去键盘都会立刻回到点。
6. **本机凭据按名字做键**：`workflow:<清单名>:input:<输入名>`。清单改名或输入改名后，旧记录就
   成了孤儿，只能去 Windows 凭据管理器里删；清除按钮只删当前名字下的那一条。
7. **画布未实现**：`src/app/flow_map.rs` 还不存在，文档里的布局是设计而不是现状。
8. **Python 步骤的 JSON 只能一个文档**：一次输出两个对象，引擎就解析不到（`verify` 因此改成"失败时也
   只发一份带 `error` 的文档"）。
9. **聊天里还没有运行块**：`Role::Run` / `render_run_block` 都还不存在，§12 是设计决定，不是现状。
10. **多 agent 没有实现**：`ai` 步骤只是"每一步一个全新上下文"（一次性问答），`dsh-flow ai --tools` 是独立
    工具循环，`task` 是独立进程。运行监督者排在 P3，且只服务"需要开放式判断"的流程。
11. **AI 内部过程尚未进左栏**：`ai` 步骤没有 `ai/delta` / `ai/reasoning` / `ai/tool` 事件，左栏只能显示
    整段回答；思考折叠与工具行要等引擎先发事件（§14.5）。
12. **步骤富文本依赖保留键**：左栏把 `text` 当 markdown 渲染（AI 步骤有），普通 `run` 步骤没有 `text`，
    stdout 仍按代码块显示；清单保留键 `markdown` 还没实现。
13. **快照只在结束时写**：运行中崩溃没有快照，只有引擎 trace；输入归属目前靠 `{{ inputs.x }}` 推断，
    Python 从环境变量读的输入会落进「运行前」卡，直到清单 `form:` 落地。
14. **右栏源码只认清单能指出的文件**：YAML 有行号片段，JSON 清单没有；`program` 取自命令里第一个
    已知扩展名的参数，解释器从别处加载的文件（`python -m pkg`）指不出来。AI 过程仍只有整段回答。
15. **历史标签只列已加载的运行**：内存最多 30 条，启动和打开工作流时各读取 30 份（引擎每个工作流
    最多保留 30 份快照）；更早的已经不在磁盘上，不再做分页。源码框滚动条现在支持点击跳转与拖动。

## 12. 决定记录（2026-11-26）：聊天里的运行块，以及为什么不用多 agent 解决它

> 这一节是**决定**，不是待办承诺。今天的代码停在上一节的状态，§12 里的东西一条都还没写。

### 12.1 结论（四条）

1. **输出用聊天渲染**：把聊天画工具行/文件卡/图片/思考的那段抽成 `render_row`，聊天与工作流页共用；
2. **一条消息 = 一个运行块**：新增 `Role::Run`，消息里只存 `run_id`（+ 输入摘要），正文现场渲染——
   **不把每个步骤当成对话消息塞进 transcript**；
3. **输入卡排在掩码之后**：先补 `TextField` 掩码与本机保存，再把输入卡放进运行块块头；
4. **不用多 agent 解决这个问题**：多 agent 只作为可选的"运行监督者"（P3），且只在需要开放式判断时启用。

### 12.2 更正一条：模型上下文不会被污染

上一轮把"污染上下文"列为反对理由，**不准确**。`split_history`（`src/app/util.rs:667`）只把
`User` / `Assistant` / `Attachment` 送进模型历史，`Tool` / `Note` / `Approval` / `Thinking` /
`Question` / `Plan` 全部丢弃。新增的 `Role::Run` 在同一个 `match` 里 `return None` 就够了。

所以真实的代价是另外三条：

| 代价 | 说明 | 多 agent 能解吗 |
|---|---|---|
| **UI 并发** | 一次运行几分钟，期间用户还会提问；`AiEvent` 与 `StepEvent` 会抢同一屏的"当前行" | 不能。两个 agent 仍是两个流 |
| **持久化与身份** | 步骤行进 `chat.json` 会胀体积、被压缩层摘要、计入 token 账本 | 不能。子 agent 的 transcript 一样要落盘、要 id |
| **工具语义与统计** | 聊天里的 `Role::Tool` 意味着"模型调了工具"，统计页也按它计数；工作流步骤是子进程 | 不能。子 agent 的工具调用仍是模型调用 |

外加一条信任边界：**秘密不该出现在任何模型能读到的地方**——agent 越多，可能被问到的入口越多。

### 12.3 多 agent 能解什么、不能解什么

| 它能解 | 它不能解 |
|---|---|
| 子任务的中间过程不进主线程窗口（窗口预算） | 一次运行怎么在聊天里显示（那是数据身份问题） |
| 给子任务一套不同的工具白名单（`browser` / `read` / `http`） | 两个流争一屏、顺序与"哪行还在跑" |
| 子任务自己的压缩策略，长运行不挤掉对话 | 运行产物的持久化、重跑、旧块保留 |
| 人机接管有一个明确的对话对象 | 输入的信任边界（反而多了一个能问到密码的入口） |

成本：每个 agent 重读一份系统提示（上下文翻倍）、需要协议（谁批准、谁取消、谁拥有浏览器）、
调试要跨两个 transcript。**只有在"流程里真的需要开放式判断"时才划算。**

### 12.4 如果将来要做，正确的切法

```
对话 agent（主线程）
   └ 工具：workflow.start / status / retry
        ↳ 只回一行摘要（"已启动 #a3f1" / "第 3 步 credential 失败" / "完成 51 条"）

运行监督者（run supervisor，P3，可选）
   ├ 自己的上下文：清单 + 上一步结果 + 页面状态 + 自己的压缩
   ├ 工具白名单：browser / read / http
   └ 自己的 transcript  ← 就是"运行块"的数据源

确定性步骤（steps/*.py）——主体，0 token
```

三条边界必须立住：

1. **监督者仍然调确定性步骤**。把 12 步变成 12 次模型调用，就丢掉了"1 个判断点 / 92% 不用模型"这个性质；
2. **只传三样东西给主线程**：启动参数（不含秘密）、进度摘要、错误分类；
3. **资源要有主**：一次运行只允许一个浏览器会话、一个 workspace 锁。两个 agent 抢同一个 Chromium
   （这条流程正是这么用的）会互相把页面导航走。

**反例**：每步一个 agent 是最差解——N 份系统提示、N 次上下文重建、步骤间共享状态只能靠消息传，
收益几乎为零。

### 12.5 决定下来的顺序

1. 共享行渲染器（`src/app/message.rs`）；
2. `Role::Run` + 运行块（只读，`split_history` 过滤）；
3. 掩码 + 本机保存（P0，必须先于第 4 步）；
4. 运行块块头的输入卡 + 重跑；
5. `workflow` 内置工具（start / status / cancel，只回摘要；引擎声明 schema、用事件请界面执行，和
   `ask_user_question` 同一条路）；
6. `ai` 过程事件（`run --events` 增加 `ai/delta`、`ai/reasoning`、`ai/tool`）；
7. 可选：运行监督者（多 agent，§12.4）。

前两步不需要任何 agent 概念，也不会因为将来上多 agent 而返工；反过来先上多 agent、再补运行块，
等于用更贵的东西解决一个不需要它的问题。

> 一句话：**多 agent 解决的是"模型窗口预算"，不是"界面里怎么显示一次运行"。**
> 这两件事分开做，都便宜；混在一起做，都贵。

### 12.6 实施更正（2026-11-27）

上面第 3 步（掩码 + 本机保存）已经先做完了，见 §13；第 1、2 步（共享行渲染器、`Role::Run` 运行块）
还没动。先做第 3 步的理由：它只碰输入卡与凭据库，不依赖运行块的数据形状；而第 2 步的块头输入卡
反过来要用这里的掩码与保存能力。所以顺序改成 **3 → 1 → 2 → 4**，前两步的逻辑不变。

### 12.7 再次更正（2026-11-27 第二轮）

实际落地时先把**布局**换掉了：左栏是“运行对话”（只读、程序驱动），右栏是带输入的步骤板（§14）。
这不是 §12 说的“助手会话里的运行块”，而是一个独立的运行渲染器；两者共用渲染组件，但数据模型分开。
如果以后要把运行块放进真正的聊天，`Role::Run`、`split_history` 过滤和“运行摘要如何让模型看到”仍需按
§12 补上；目前的左栏不参与模型上下文。

### 13.2 一个 secret 输入从打开到运行

1. 选工作流 → `rebuild_inputs`：清单说 `secret: true` 的输入先查本机凭据库；有值就填回并记为
   `stored`，没有就是空框（占位符写「只在界面上填写」，不再说 `default`）。
2. 渲染：`field_masked` 让框里画点；卡片第二行来自 `ManifestSpec::consumers`。
3. 「按住显示」只改 `revealed_input`；`leave_fields`、`start_run`、`select_flow` 都会清掉它。
4. 「保存到本机」走同一条 `SecretStore`（Windows 凭据管理器）；「清除」删库并清框。
5. 点「运行」：`start_run` 先查必填为空（拦下），再把 secret 从 `--input` 里拿掉、改走 stdin；
   日志首行与运行记录里只有 `***`。

### 14.3 两条硬规则（别再踩）

- **一个输入只有一个可编辑控件**：`FieldElement` 把 bounds 按槽位记在 `field_bounds` 里，同一槽位
  画两次，后画的覆盖前者，点击定位和光标就会错位。所以左栏只显示只读值，编辑只在右栏卡片上。
- **两栏的 element id / markdown 状态必须分命名空间**：左栏 markdown 用
  `TRANSCRIPT_MESSAGE_BASE + 步骤序号`，`<details>` 展开集合、代码块滚动句柄、复制高亮都按这个 id
  走，才不与聊天消息撞。

### 14.4 快照里有什么、没有什么

- 有：每一步的 `id/kind/status/durationMs/detail/command/stdout/stderr/text/model/cached/summary`、
  `artifacts`（kind/name/absolute path/bytes）、结构化 `error`；整段日志；本次输入（密钥为 `***`）。
- 没有：引擎 trace 里的服务事件 / 未来 AI 事件（`ai/delta`、`ai/tool` 等）——快照只存界面知道的；
  更细的引擎侧证据仍在 `<workspace>/.dsh-flow/runs/<runId>.jsonl`。
- 只在**运行结束**写一次：运行中崩溃不会有快照（trace 仍在）。这是下一轮“边跑边存”的边界。

### 14.12 第九轮（同日）：步骤单线宽行、运行按钮三态、新建运行

- **步骤外观**：`render_board_card` 去掉 `bg(panel)` 与 `shadow_sm`，改用 `w_full` + 1px 边框 +
  `rounded_md` 的宽行；未选中边框 `border`，选中 `sky`。内容层级不变：收起只留标题/描述/必要输入，
  展开才显示计划说明、条件/保存/备注与源码。
- **运行按钮三态**：`render_board_bar` 只保留一个按钮，按 `pane.running` / `pane.outcome` 切换

  并回到当前标签，左栏因此显示空状态、右栏输入恢复可编辑；记录早在运行结束时已落进历史。

  只在 `flow_cleared` 不含该工作流时才自动选中最新记录；`start_run` 与 `push_record` 会移除这项标记。
